一块摆在桌面上的追番表：**这一季有什么、什么时候播、下一集几点更新、欠着的番还剩几天**，一屏看完，不用再开五个网站对着翻。

Windows 桌面小工具，自带 2026 年 4 / 7 / 10 月三个季度共 **219 部真实番剧数据** —— 装好第一次打开就有内容，不用登录、不用联网、不用开代理。

名字取自日语里的「次回予告」，也就是下集预告。这块表盯的正好就是这件事：下一集什么时候来。

![本季番剧](screenshots/01-season.png)

## 装上跑起来

先装 [Node.js](https://nodejs.org/) 18 或更高版本，然后在项目目录里：

```bash
npm install
npm run desktop
```

不想敲命令的话，直接双击仓库根目录的 `启动次回.bat`，它会自己检查依赖和构建产物，缺什么补什么，直到窗口弹出来。

本版发布的是源码，**没有做安装包**。只做了 Windows 一期，macOS / Linux 没有验证过（代码里没有平台硬编码，理论上能跑）。

## 它替你记的四件事

### 一、这一季有哪些，我追哪几部

按季度（冬 / 春 / 夏 / 秋）切换，季度标签写成「2026 年 7 月 · 夏」这种一眼能认的形式。每张卡片给你封面、中日文名、制作公司、评分，**右上角点一下星标就算追上了**，不用进详情页。顶部搜索框实时过滤，中日文名、制作公司、标签都能命中。

封面是真封面；万一系列里某部没有封面、或者图挂了，会按标题生成一块渐变色块顶上，不会留一个破图框。

点任意卡片会从右侧滑出详情抽屉，简介、标签、话数、以及去 Bangumi 和萌娘百科的外链都在里面：

![详情抽屉](screenshots/05-detail.png)

### 二、什么时候播

七天视图，从周一排到周日，今天那一列高亮并标出日期。

![播出时间表](screenshots/02-schedule.png)

两处跟别的时间表不一样的地方：

- **按北京时间归组，不是日本时间。** 数据里的时间是 UTC，但「星期几」必须按日本电视台的排播习惯（JST）取，显示给你看的时间和归组按北京时间（CST）算。日本写「周三 25:30」的那一集，会正确地落在周四凌晨那一块里 —— 要是直接拿 UTC 取日期，整张表的星期会集体错一天，周日那一列还会永远空着。
- **深夜档单独成块。** 当天 18:00 到次日 06:00 会播什么，单独列出来。真正熬夜等更新的人都在这段时间里，把它折叠进「前一天」就等于藏起来了。

右侧还有一块「今日更新」，按时刻排出今天所有的排播。

### 三、下一集几点更新

追番队列不按番剧名排，**按「下一次更新时间」排，刚更新的排最前** —— 打开就知道现在该看哪个。

![追番队列](screenshots/03-following.png)

- 每条都有倒计时：`2 天后` / `5 小时后` / `18 分钟后`，已经播过的转成「3 小时前已更新」；
- **「我落后了」和「番停更了」是分开的**：前者提示「攒了 N 话没看」，催你补；后者不报警，因为那不是你的问题；
- 支持「在看 / 想看 / 搁置 / 弃了」四种状态。标成搁置或弃了会自动关掉提醒，不再打扰；
- 右下角用七格小条形图显示下周哪天有更新，一眼看出哪几天是重灾日。

### 四、欠着的番还剩几天

自己给每部补番定个 deadline，它会一直提醒你到补完为止。

![补番清单](screenshots/04-catchup.png)

- 每部一张卡，**三档配色**：已逾期（红）/ 三天内（黄）/ 时间宽裕（灰），补完的转暗色沉到最底下；
- 进度条直接告诉你还剩几话，卡上写着还剩几天；
- 逾期数量在侧边栏和概览里单独计数 —— 想装看不见也不行。

## 顺手做好的几件事

### 布局能拖，拖乱了能一键回来

每个视图由几块「窗口卡片」拼成，**拖着换位置、拖右下角改大小**，摆完自动记住，下次打开还是你摆的样子。

![布局预设](screenshots/11-settings-layout.png)

怕拖乱了找不回来，所以额外给了 4 套内置预设（默认宽屏双栏 / 专注主卡优先 / 纵向堆叠 / 紧凑小窗总览），一键切换。也能把当前摆位存成自己的预设，重命名、删除都行。预设可以导出成 JSON 再导回来，换电脑不用重新拖一遍。

窗口拉窄到 1180px 以下时，卡片自动改成单列堆叠，不会出现横向滚动条：

### 能给窗口换张壁纸

挑一张本地图片当背景，自动缩到长边 1920 再存下来，不会因为塞进一张原图把体积撑爆。

不透明度、模糊、亮度、缩放、位置、暗角**六项都能单独调**，调的时候实时看着效果：

![壁纸 + 卡片半透明](screenshots/07-wallpaper.png)

卡片和侧栏的不透明度可以另外压低，让壁纸透出来而不是被糊住；侧栏和顶栏会自动比卡片更实一点，否则整个界面会飘。

![外观设置](screenshots/09-settings-look.png)

![高模糊低暗角](screenshots/08-wallpaper-blur.png)

### 关掉窗口也还在

提醒这件事，如果只在窗口开着时有效，那基本等于没有 —— 谁会整天把窗口摆在最前面。所以：

- 关窗**不退出**，收到托盘里继续跑；最小化也可以收托盘（两项都能关）；
- 托盘右键菜单能直接跳视图，并且显示**今天有几部更新、待补几部、几部已逾期**；
- 开机自启走系统登录项，启动时带 `--hidden`：**开机后静默进托盘，不弹窗**；
- 全局快捷键（默认 `Ctrl+Shift+A`）在任何程序前台时都能呼出和收起主窗口。被别的软件占用了会明确告诉你，不会静默失效。

![提醒与托盘](screenshots/12-settings-remind.png)

### 快捷键

按 `?` 随时呼出帮助浮层：

![快捷键](screenshots/14-shortcuts.png)

`1/2/3/4` 切视图、`/` 聚焦搜索、`R` 同步、`T` 换配色、`B` 开关壁纸、`L` 布局预设、`,` 打开设置、`Ctrl+R` 刷新、`Esc` 清空搜索或关掉浮层。

光标在输入框里的时候，单字符快捷键会自动让路（`Esc` 和 `Ctrl` 组合除外 —— 搜完按 Esc 没反应是很恼人的）。

## 数据打哪儿来

设置里三档可选，默认第一档：

| 模式 | 说明 |
| --- | --- |
| **自带数据（默认）** | 随包带上 2026 年 4 / 7 / 10 月三个季度共 219 部真实番剧，**离线可跑、不用联网、不用开代理** |
| bangumi-data | 拉 [bangumi-data](https://github.com/bangumi-data/bangumi-data) 的真实番剧表（CC BY 4.0）按季度过滤。**不含**话数 / 评分 / 封面 |
| bangumi-data + Bangumi API | 在真实排播基础上，用 Bangumi v0 API 补齐话数、评分、封面、简介、制作公司 |

![数据源设置](screenshots/10-settings-data.png)

**默认不联网是刻意的。** 国内直连 `api.bgm.tv` 常常不通（域名能解析，但 TCP 直接超时），如果默认就去联网，第一次打开软件的人会看到一个空界面加一条报错。自带数据把这条最差路径直接消掉了：先有东西看，想看最新的再自己去开代理同步。

自带的那份**是真的，不是演示数据**：条目全部来自真实番剧表，先取 bangumi-data 的快照，再逐条用 Bangumi v0 API 补齐话数、评分、封面、简介、制作公司，然后随仓库一起发布。（那份全虚构的数据已经挪到 `test/fixtures/`，只服务测试，不随产品发布。）

### 联网这件事，程序会把话说清楚

国内直连 `api.bgm.tv` 需要走代理。桌面版的请求走的是 Electron 的 Chromium 网络栈，**会自动跟随系统代理 / VPN**，不用在本作里改任何配置；也可以在「数据源」里手填代理地址，或者填一个自建反代（只放行 https，http 只允许本机）。

三种办法在设置里都有，旁边还有「诊断」按钮逐个试端点，并且会把 Chromium 的错误码翻成人话（「连接超时（网络不通，或被墙 / 需要开代理）」这种），而不是甩一串 `ERR_` 给你。

同步的时候顶部会给真实进度，而不是一个转圈的图标：

![同步中](screenshots/06-syncing.png)

同步出问题时，界面顶部不会默默降级，而是挂一条横幅说明现在看到的到底是什么：

| 情况 | 横幅写什么 |
| --- | --- |
| 选了联网源但完全拉不到，退回自带数据 | 真实数据源不可用，已回退到自带数据（原因） |
| 连自带数据里也没有这一季 | 这一季没有自带数据，联网同步试试（原因） |
| 网络不可用但有旧缓存 | 网络不可用，暂用上次缓存（原因） |
| 排播表拿到了但补全全失败 | 补全失败，只拿到了排播表（原因） |

否则你会以为看到的是真实数据，那比报错更糟。

### 缓存和用户数据分开存

一个季度的完整番剧表（含简介和标签）和「追番 / 进度 / 补番 / 布局」这些**你自己的东西是分开存的**。缓存丢了只是重下一遍，自己的数据丢了才是灾难。

设置里能看到每个季度缓存多大、什么时候存的、补全了多少条，可以单个清，也可以全部清；最多保留 10 个季度，超了淘汰最旧的。你的数据存在 Electron 的用户数据目录里（Windows 上是 `%APPDATA%\jikai\`），壁纸因为体积大，单独放在 `wallpaper.json`，不跟主状态文件混在一起。

## 已知限制

- **没有安装包。** 目前靠 `npm run desktop` 或双击 `.bat` 起，所以自动更新只能做「检查 + 跳去下载」，没有静默替换 —— 这一项的界面入口当前是收起来的（实现是完整的、也有测试，只是还没有发布渠道，先不让它露出来）；
- 只做了 Windows 一期，macOS / Linux 未验证；
- 开机自启在开发模式下注册的是 electron.exe 本身，打包成安装包后这段逻辑才真正干净；
- 托盘图标只有一种状态，没有按「今天有几部更新」换图标；
- 换主题没有过渡动画；
- 壁纸单张上限约 3.2MB（转成 base64 会膨胀约三分之一），且只存一份、不分视图。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 界面 | React 18（纯函数组件 + Hooks，没上 UI 框架） |
| 构建 | Vite 5 |
| 桌面壳 | Electron 33（主进程 / 预加载脚本分离，`contextIsolation` 开启） |
| 状态 | 自研轻量订阅式 store |

**运行时依赖只有 React 和 React-DOM 两项**，其余都在 devDependencies。测试用 `node --test`，101 个用例，含 6 个服务端渲染断言。
